# ControlCenter replacement (pearOS ControlCenter in place of Apple's, macOS 26.7.2)

Goal (user, 2026-11-18): our own ControlCenter that can replace the real one on a real macOS, like `apps/dock-cocoa` does for the Dock; **same XPC services and same SkyLight calls** as the real one. Method = the Dock's: trace the real process with dtrace, reproduce, compare (`research/dock-trace/compare.py`), REA for what a trace cannot tell (prototypes, call sites).

## What the real ControlCenter is (Mac VM, 26.7.2)
- `/System/Library/CoreServices/ControlCenter.app`, launchd job `com.apple.controlcenter` (`/System/Library/LaunchAgents/com.apple.controlcenter.plist`): MachServices `com.apple.controlcenter.ccutil`, `com.apple.SystemBannerService`, `com.apple.SystemBanner`, `com.apple.controlcenter.controlcentermodule`, `com.apple.controlcenter.show.toggles` (HideUntilCheckIn), `com.apple.controlcenter.statusitems`, `com.apple.usernotifications.delegate.com.apple.controlcenter.notifications.airplay`; KeepAlive SuccessfulExit=false, ThrottleInterval 1, Aqua only. Unlike the Dock it IS an AppKit/SwiftUI app (links ControlCenter.framework, CoreWLANKit, CoreBrightness, DisplayServices, Focus, DoNotDisturb, SidecarCore, ...).
- It owns the **menu-bar status items** (windows at level 25, owner "Control Center": Spotlight 1063,0 31x30; Control Center icon 1094,0 42x30; clock/date 1136,0 144x30 on a 1280x800 display) and the **panel** (window level 22, 800,0 656x964 incl. margins; visible panel x 967..1273, y 35..561, opens on a click of the icon).
- Panel content (reference screenshot, no network/Bluetooth hardware on the VM): top "System recently" pill; Wi-Fi / Bluetooth / AirDrop tiles (state "Off"); Now Playing tile; Stage Manager and Screen Mirroring round buttons; Appearance (dark/light) button, Screenshot button, Focus pill; Display slider; Sound slider (+ AirPlay button); "Edit Controls" pill. Panel colour ~ (61,61,61), tiles (111,111,111) over a white desktop (material/blur not measured yet).

## Startup trace (research/cc-trace)
`capture.sh` = dtrace of the real process (`launchctl kickstart -k` while `dtrace -W` waits; `killall` does NOT work here: the trace stops after 5 lines); `real-controlcenter-startup-macos26.7.2.txt` (1864 lines: 34 LOOKUP, 84 XPCSVC lines, 1098 PREF, 226 SLS, 16 OBJC, 400 OPEN). `trace-ours.sh` + `cc-switch.sh ours|real|stop` run ours as job `com.pearos.controlcenter` (same MachServices as Apple's plist; Apple's job booted out) and trace it the same way. Always restore with `sh cc-switch.sh real`.

## SkyLight: the status-bar path (dtrace args, `sbargs*.d`, results `sbargs*-real.txt`)
Each status item = `SLSNewWindowWithOpaqueShape[AndContext](cid, type 5, region, opaque, options 0x10000, tags, ...)` then `SLSSetWindowClientPerceivedType(cid, wid, 5, ...)`, `SLSCreateLayerContext` + `SLSSetWindowLayerContext`, `SLSSetWindowEventMask`, `SLSSetWindowTitle`/`SLSSetWindowProperty`, `SLSAddTrackingRegion`, then in ONE transaction: `SLSTransactionSetWindowTags` (x2), `SLSTransactionSetWindowShadowProperties`, `SLSTransactionSetWindowLevel(tx, wid, 0x19=25)`, **`SLSTransactionSystemStatusBarRegisterSortedWindow(tx, wid, sortKey, identifier, 0x590|0x490, 0|2)`** (sort keys 0x7ffffff5 and 0x7fffffe1: positions counted from the right edge), `SLSTransactionSystemStatusBarSetItemPrivacyIndicator`; afterwards `SLSSystemStatusBarGetWindowPreferredPosition(cid, wid, &out)`, `SLSCopySystemStatusBarMetrics`, `SLSPackagesSetWindowConstraints`. The 4th argument of RegisterSortedWindow is an object (the dump shows a string/UUID-like value): **REA (SkyLight pseudo-code, 2026-11-18): the prototype is `(tx, wid, int key, CFString ident, uint a, int b, float f, uint last)`** (opcode 0x3a in the transaction stream; the real ControlCenter does NOT call it itself: REA found no reference in the binary, AppKit's NSStatusBar does, `systemStatusBar` is imported); the other prototypes still to be taken with REA (thin x86_64 slice of the ControlCenter binary + SkyLight from the cache).
In the real process these are called by AppKit (NSStatusItem / NSStatusBarWindow); ours calls SkyLight directly (the Dock's method) so that it runs on pearOS's SkyLight too.

## Panel (2026-11-18)
`CCPanel.m`: window 800,0 656x964 at level 22 (the real one), panel x 966..1274, y 34..533 (r 37), tiles measured on the real panel (Wi-Fi/Bluetooth/AirDrop 140x63, Now Playing 140x140, round buttons 63, Display/Sound 292x63, Edit Controls pill), colours panel 61 / tile 111 / icon disc 147 / white button, labels and sliders drawn with Core Graphics + Core Text (glyphs are vector approximations, not SF Symbols). Opens on a click of the Control Center item, closes on a click outside (`CCInput.m`: CGEvent tap scaffolding; TCC rows for com.apple.controlcenter are set by `research/cc-trace/deploy-ours.sh`). Pixel comparison of the panel area against a screenshot of the real one (Wi-Fi and Bluetooth off, nothing playing): mean difference 4.5 / 255 (first draw 21.5: a colour-space conversion made the greys lighter; fixed by using the bitmap's own RGB space). Not done: the real material (blur/vibrancy: the real tiles are translucent over the wallpaper), shadow, states and actions (all tiles are static), the top "System recently" pill, SF Symbols glyphs, animations.

## Controls, edit mode, gallery (2026-11-18)
Model (`CCControls.m`): a catalog of 25 controls (the default 11 plus the gallery's: Alarm, Stopwatch, Timer, Scene, Tile Windows, Run Shortcut, Voice Memo, Quick Note, Recognize Music, Start Screen Saver, Keyboard Brightness, Lock Screen, Fast User Switching, Battery, Clock), a 4-column grid (pitch 76.33 x 76, cell 63, measured on the real panel), layout saved in the preference key `pearos.CCLayout` of `com.apple.controlcenter` (the real layout store was not found: only `ControlCenterDisplayableChronoControlsProviderConfiguration` and `NSStatusItem` keys are visible). Panel (`CCPanel.m`) draws from the model; **Edit Controls** = edit mode like the real one: minus badges on every control (click removes), empty slots (2 extra rows, panel grows to y 644), the "+" button in the menu bar (window 1046,0 48x30), drag a control to another free cell, **gallery window** (`CCGallery.m`, level 23, 736x670 at 226,45): search field (typing filters, Escape or Done closes), 17 categories, What's New banner, Suggestions, one section per category, click on a control adds it to the first free place. Input: CGEvent tap (mouse down/drag/up, scroll, keys).
Actions (`CCPerform`): Dark Mode toggles the system appearance (SLSSetAppearanceThemeLegacy, verified: the whole system switches); Wi-Fi (CoreWLAN setPower), Bluetooth (IOBluetoothPreferenceSetControllerPowerState), AirDrop (com.apple.sharingd DiscoverableMode), Stage Manager (com.apple.WindowManager GloballyEnabled), Focus (our key: the real toggle goes through the DoNotDisturb framework, not done), Screenshot / Clock / Voice Memos / Notes / Shortcuts / Screen Saver launch the app, Screen Mirroring opens the Displays settings, Now Playing play/pause through MediaRemote, Display and Sound sliders (drag; DisplayServices brightness; volume is stored only: no audio device on the VM). The VM has no Wi-Fi, Bluetooth, audio or display hardware, so those calls are written but **not verified**; only the appearance toggle and the layout editing are.
Detail pages (`CCPageRows`): a click on the label area of Wi-Fi, Bluetooth, AirDrop, Focus or on the title of Display / Sound opens the small page that replaces the panel (measured on the real Wi-Fi page: 308 x 82 at 964,36, radius ~20, switch on the title row with a 57 x 24 track and a 32 x 20 knob, divider, "Wi-Fi Settings…" link; pixel difference 3.1 / 255). The pages of the other controls follow the same shape but were NOT compared with the real ones. Now Playing polls MediaRemote once a second (title, artist, artwork, play state; checked only for the "nothing plays" case).
Menu-bar extras (`CCExtras.m`): Battery, Wi-Fi, Bluetooth, Sound, Focus, Now Playing, Screen Mirroring, Display, AirDrop, Stage Manager, Keyboard Brightness, user switcher, right to left from the left edge of the Spotlight item (32 wide each), shown when `NSStatusItem VisibleCC <name>` of com.apple.controlcenter is true AND the hardware exists (battery via IOPS, Wi-Fi via CoreWLAN, Bluetooth controller, Focus active). On the Mac VM the REAL ControlCenter shows none of them even with the keys set (checked: no Wi-Fi/Bluetooth/battery hardware), so the look of the extras is NOT compared with the real one; our test switch is the key `NSStatusItem VisibleCC pearos.forceExtras`. A click on an extra opens the page of its control under it.
**Focus (real, 2026-11-18):** through the DoNotDisturb framework (`DNDModeAssertionService` client `com.apple.controlcenter.dnd`: take / read / invalidate an assertion; mode ids `com.apple.donotdisturb.mode.default`, `com.apple.sleep.sleep-mode`, `com.apple.focus.personal-time`, `com.apple.focus.work`). Verified on the Mac VM: the tile turns purple and reads "Do Not Disturb", a separate probe sees the active assertion, a second click ends it. It only works because our binary is signed ad hoc WITH the real ControlCenter's entitlements (`codesign -d --entitlements :- .../ControlCenter`; the ones that matter: `com.apple.private.donotdisturb.*.client-identifiers` containing `com.apple.controlcenter.dnd`, `com.apple.security.temporary-exception.mach-lookup.global-name` with `com.apple.donotdisturb.service`); a process without them gets `BSServiceConnectionErrorDomain 3`.
**FreeBSD bindings (temporary, user's request 2026-11-18), `CCPlatform.c`** (plain C, from the earlier Control Center `apps/topbar/ControlCenter.m` plus new ones): volume = `mixer(8)`, brightness = `backlight(8)` or `hw.acpi.video.lcd0.brightness`, battery = `hw.acpi.battery.*`, keyboard backlight = `dev.clevo_dchu.0.kb_brightness`, Wi-Fi = `ifconfig wlanN up/down` (UP flag; used when CoreWLAN is absent), Bluetooth = `ngctl list` (ubt node + hci) and `service bluetooth onestart/onestop` (used when IOBluetooth is absent), Focus = usernoted over NSXPC (`setFocus:` / `focusWithReply:`, protocol of d/bsd/usernoted; used when the DoNotDisturb framework is absent), appearance = `AppleInterfaceStyle` of `~/Library/Preferences/.GlobalPreferences.plist` (when SkyLight has no `SLSSetAppearanceThemeLegacy`). The macOS framework is tried first, the FreeBSD binding is the fallback, so the same source runs on both. Tested on the FreeBSD VM (14.5): `make check-platform` in `apps/controlcenter-cocoa` (no devices there: every getter returns "none", every setter refuses; with fake `mixer`, `backlight`, `ifconfig`, `ngctl`, `service` scripts in `test/fake.sh` the values read and change correctly). Not run on a machine with the real hardware, and the usernoted / appearance fallbacks have not run on pearOS yet (only compiled on the Mac).
**Symbols (2026-11-18, after the owner asked whether the repo's Assets.car were used: at first they were NOT, glyphs were vector drawings):** `CCSymbols.m` now draws the real SF Symbols from the Mac's own catalogs at run time with CoreUI (`CUICatalog namedVectorGlyphWithName:...`, `rasterizeImageWithTintColor:usingScaleFactor:forTargetSize:`): `CoreGlyphs.bundle` (public) and `CoreGlyphsPrivate.bundle` (bluetooth, airdrop ...); nothing of Apple's is stored in a repository. The catalogs in `CoreUI/catalogs/` were checked: `ControlCenter/Assets.car` and `ControlCenterHelper/Assets.car` hold only legacy/auxiliary art (knob, slider-fill, MenuExtra-*.pdf, ExtendDisplay, MirrorDisplay), not the Tahoe toggle glyphs; those are SF Symbols (public ones are in `CoreGlyphs`, which is NOT in the repo yet: 105 MB, see CoreUI/README.md; the private ones are in `CoreUI/catalogs/CoreGlyphsPrivate`, 1655 names). Finding: with both CUICatalog objects alive the public one stops finding names, so only one is open at a time. Mapped so far: wifi, wifi.slash, bluetooth, moon.fill, circle.lefthalf.filled, play/pause/forward/backward, speaker, speaker.wave.3, airplay.audio, rectangle.on.rectangle, sun.min/max, alarm, stopwatch, timer, lock ... (`symbolFor` in CCDraw.m); AirDrop, camera.viewfinder and Stage Manager still use the vector fallback (the private airdrop symbols are layered and rendered as a dot by this call; camera.viewfinder did not render). Panel difference against the real screenshot stays at 4.4 / 255.
Not done: dragging from the gallery (click instead), resize of a control (the real panel lets 1x1 controls become 2x1 etc.), lists inside the pages (networks, Bluetooth devices, sound outputs, Focus modes), the other menu-bar extras (Wi-Fi, Bluetooth, battery, Focus, volume...), real SF Symbols, the sidebar's coloured icons, material/blur.
